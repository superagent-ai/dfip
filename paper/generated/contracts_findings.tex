GLiNER passes all 18 schema/size gates and the exposed-label/confidence audits. Shared scheduling improves the resident median by 1.08$\times$ on recurring schemas and 1.57$\times$ on diverse schemas relative to native batching (2.92$\times$ and 1.92$\times$ relative to serial). This is an incremental scheduling result in one worker, not evidence of a new GPU kernel. On diverse scheduled arrivals, p95 is 127.9\,ms for shared scheduling and 127.9\,ms for native batching; both complete all 256 requests without drops. The resident gain therefore does not establish a tail-latency advantage over native batching in this replay.

Omni, D3 and both JEV sizes reject every tested shared batch size under the frozen gate and execute single-request native fallback. Omni and D3 preserve the held-out shared answer fields but gain no meaningful speed over serial, and are slower than ungated native batching. Both JEV native-serial and shared-fallback audits exceed numerical tolerances; JEV-27B also changes selected answers during serving. These findings do not isolate an optimizer-induced numerical error, since shared batching was never admitted. The strict gate is unsuitable as a universal equivalence certificate when the native reference itself varies.

Table~\ref{tab:contracts-serving} reports completed-request latency together with all drops. The conservative fallback still overloads on the diverse trace: D3 drops 41/256 requests, JEV-9B 132/256 and JEV-27B 61/256. Ungated native batching completes all offered requests for these models, but fails the exposed-answer fidelity gate. Choosing a slower path preserves neither a latency objective nor complete request delivery by itself. A useful general optimizer must improve on the strongest native baseline under an application-specific answer contract, rather than count native fallback as an acceleration.

A post hoc GLiNER follow-up calls the released FP32 \texttt{Extractor.compile()} before repeating the same policy and fixtures. All three modes then use that compiled substrate, with eager references collected before compilation in the worker. Shared scheduling admits 18/18 gates and passes the resident audit; its diverse resident ratio is 1.40$\times$ relative to compiled native batching. Diverse p95 is 72.1\,ms for shared and 43.2\,ms for compiled native batching. The fixtures were reused after inspecting the primary result, so this is a stronger-baseline diagnostic rather than independent confirmation. Compiler invocation and first-use compilation in admission are retained outside the warm resident ratios.
