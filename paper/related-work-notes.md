# Reading notes for the focused DFIP review draft

These notes paraphrase methodological lessons from primary papers; they contain no copied passages. The current manuscript studies PPLX-Decider, Liquid d1-3B, Clef-Flash, and GLiNER2.5-Decide. It does not claim that CUDA replay, constrained selection, candidate projection, or token-budget batching are new mechanisms.

| Primary source | Sections read | Consequence for the study |
| --- | --- | --- |
| [SGLang](https://arxiv.org/abs/2312.07104) | Design, evaluation setup, end-to-end performance, ablations, production case study | Treat structured selection as an existing primitive. Measure the full released decision path, not a generic generation path with different semantics. |
| [PagedAttention/vLLM](https://arxiv.org/abs/2309.06180) | Design, implementation, experimental setup, serving results, ablations | Specify the native substrate. Resident serial latency does not establish arrival capacity or concurrent throughput. |
| [PyGraph v3](https://arxiv.org/abs/2503.19779v3) | Introduction, compatibility constraints, transformations, replay overhead, evaluation setup, component ablations | Isolate replay from projection. Include buffer copying, admission, recapture, and failures in the system interpretation. A small graph cache is not a new compiler. |
| [Triton](https://www.eecs.harvard.edu/~htk/publication/2019-mapl-tillet-kung-cox.pdf) | Programming model, related work, matrix-multiply evaluation | Compare the custom projection with cuBLAS and the whole request. Less arithmetic is not sufficient evidence of latency benefit. |
| [MLPerf Inference](https://arxiv.org/abs/1911.02549) | Benchmark design, scenarios, quality constraints, metrics | Separate output fidelity, warm latency, arrivals, loss, and throughput. DFIP is not an MLPerf submission. |
| [BANKING77 source paper](https://arxiv.org/abs/2003.04807) | Abstract and dataset provenance | Use a separately sourced intent corpus while acknowledging derived schemas, correlated views, and unknown checkpoint training overlap. |
| [GLiNER2](https://arxiv.org/html/2507.18546v1) | System design, classification interface, efficiency measurement, Appendix A classification readout, Appendix B experimental setup | Preserve the library's exposed label and confidence. Categorical score buckets are not an ordinal expectation. The earlier paper gives architecture context, not implementation identity for the newer Decide checkpoint. |
| [Sarathi-Serve](https://arxiv.org/html/2403.02310v3) | Introduction, serving metrics, sections 3.2 and 4.1–4.3 | Batching requires latency and work budgets as well as throughput measurement. Include native batching and scheduled-arrival comparisons; DFIP does not implement Sarathi's chunked-prefill scheduling. |

The rewrite follows a problem, native contract, execution path, method, results, and limitations structure. Its claims lead with measured acceleration over stronger native baselines and retain the adverse numerical and serving findings for the same four checkpoints. Protocols remain separate: the original eager-image Liquid component ablation, stronger-native replay study, literal answer audits, external serving, bounded-admission pilot, and GLiNER eager/compiled batching pilots are not pooled.

The main repeated timing unit is a container round. Intervals resample paired container medians rather than individual calls. Clef's four-of-five native comparison is conditional on retained rounds, with its native-preflight CUDA failure disclosed. The bounded-admission pilot retains the whole excluded worker-replacement comparison. GLiNER has one worker per execution substrate and no independent-worker interval; the compiler follow-up is post hoc and reuses the fixtures after the eager result.

Implementation source was inspected separately: the pinned Liquid runner compiler option and alias readout, Clef loader and literal-field rounding, Decider's noncausal attention contract, GLiNER2 2.1.0 single/batch/compile entry points, Transformers 5.17.0 optional Qwen kernels, and PyTorch 2.14 graph/compile documentation. These checks establish the tested native interfaces rather than additional research contributions.

The numerical contract is evaluated at the fields users consume. Clef's unchanged choices coexist with changed confidence thresholds. Liquid's released compiler speed comparison also has a different observed numerical deviation from eager. The GLiNER released-compiler resident gain is therefore reported alongside its worse diverse-arrival p95, rather than characterized as a uniform serving improvement.
