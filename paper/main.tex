\begin{abstract}
Open decision models return categorical distributions, Boolean confidences, or ordinal scores, but their inference paths can retain substantial host dispatch and full-vocabulary projection. We study a decision-focused inference path (DFIP) that preserves released prompt and readout contracts while applying selective CUDA graph replay and candidate-token projection. Pinned checkpoints from Liquid AI, Cloudflare, Perplexity, Superagent, and Supersonic Labs run on Modal GPUs. We separate randomized paired resident measurements, component ablations, diagnostic workloads derived from BANKING77, optimized-native comparisons, and external open-loop serving tests. With optional native Qwen kernels installed, retained short Boolean runs yield 2.47$\times$ for PPLX-Decider over five containers and 1.45$\times$ for Clef over four of five planned containers; Clef's fifth fails in native preflight. Against Liquid's released compiler setting, DFIP is effectively tied on the Boolean workload and has no general latency advantage across three short workloads. Graph replay supplies most of the initial gain, while candidate projection alone does not establish a general speedup. Direct audits of 3,024 decisions preserve returned choices for Decider and Clef, but Clef changes scores and probabilities; matched serving traffic also crosses sampled returned-confidence thresholds. Sustained changing-request traffic exposes queueing, overload losses, and replay-path CUDA errors beyond resident-call measurements. Concurrent dispatch to native SGLang sustains nearly 30 requests/s in the tested Security-One configuration without drops. The review artifact retains per-call samples, request accounting, failure traces, pinned revisions, and source snapshots. The contribution is a bounded empirical characterization of established techniques and their fidelity and serving limits, rather than a new graph algorithm or production readiness certification.
\end{abstract}

\section{Introduction}
Routing, policy classification, and structured scoring often require a small answer set. In these applications, inference returns a decision distribution rather than an open-ended continuation. A deployment can therefore spend much of its request time on tokenization, Python dispatch, GPU launch overhead, and output computation whose results are discarded. Reducing this work is attractive for both latency and compute cost, but the relevant contract includes calibrated probabilities and ordinal scores as well as the winning label.

Existing serving systems already support structured programs and constrained selection. SGLang, for example, includes a selection primitive and exploits execution structure in its runtime~\citep{sglang}. CUDA graphs and compiler transformations likewise provide established tools for reducing launch overhead~\citep{pygraph,cudagraphs}. DFIP does not introduce these ideas. Our question is how far a small, model-aware implementation can apply them to recently released open decision checkpoints without silently changing their interfaces or numerical behavior.

We ask four research questions. \textbf{RQ1:} Which released inference paths benefit from selective replay relative to stronger native baselines across short, long, batched, and multi-question workloads? \textbf{RQ2:} How much improvement comes from graph replay versus candidate projection? \textbf{RQ3:} Which optimizations preserve decision and probability behavior, and where do they fail? \textbf{RQ4:} Do resident-call gains survive changing external arrivals? Our contribution is a reproducible implementation and empirical characterization with negative results, rather than a universal acceleration claim.

The artifact is available for author review at \url{https://github.com/superagent-ai/dfip}. At this draft stage the repository is private; public artifact access and a frozen release must be resolved before submission. The implementation uses Python for adapters, validation, and orchestration, and Triton~\citep{triton} for experimental GPU kernels. All checkpoints and benchmark datasets remain on Modal; a lightweight local client sends structured requests.

\section{Decision Contracts and Scope}
An input contains a state $s$ and a set of typed questions $Q$. A choice question returns probabilities over a finite set of criteria; a Boolean question returns a confidence in the affirmative answer; an ordinal question returns a distribution over ordered levels and may expose its expected score. The checkpoints implement these contracts using different prompt encodings and different heads. A common client interface does not imply interchangeable internal computation.

Julia-1 uses a ModernBERT-based encoder and marker-oriented decision readout. Liquid's d1-3B uses its released LFM-based engine, including a packed trunk/branch path for multiple questions. Clef-Flash uses a Qwen backbone and a joint schema head. PPLX-Decider uses its released Qwen-based decision model. Security-One is evaluated through its SGLang path~\citep{julia,liquid,clef,decider,security}. We retain each released prompt construction, candidate ordering, alias handling, temperature, and answer conversion. We do not train, quantize, or distill the checkpoints.

These are five selected checkpoints, not an exhaustive sample of the Hugging Face decision-model tag. Text-only workloads are tested even when a checkpoint supports images. Tests do not establish safety, deployment suitability, or superior task quality. We also do not compare with generic one-token generation as though it were a semantically identical baseline.

\subsection{When candidate projection is valid}
Let $h\in\mathbb{R}^{d}$ be the hidden vector at a released answer position and $z=Wh$ the vocabulary logits. For a native readout that groups answer-token aliases $A_c$, a representative contract is
\begin{equation}
 r_c=\max_{t\in A_c}z_t,\qquad
 p_c=\frac{\exp(r_c/\tau)}{\sum_j\exp(r_j/\tau)}.
\end{equation}
If $U=\bigcup_c A_c$, computing $W_Uh$ preserves these readout logits in real arithmetic. A common log-normalization constant cancels when the selected scores are subsequently normalized over candidates. The condition is that the released readout consumes only the covered token groups: arbitrary generation, a full-vocabulary confidence, top-$k$ operations over the entire vocabulary, or an incomplete alias union do not satisfy it. Other decision heads need their own contract analysis.

This identity is not a finite-precision equivalence theorem. A smaller matrix multiply can choose a different reduction order or precision path. If $\|p-\hat p\|_\infty\leq\epsilon$, an argmax with a margin greater than $2\epsilon$ is preserved, while a threshold comparison at $a$ is preserved only when $|p_c-a|>\epsilon$. For ordinal levels $v_c$, expected-score drift is bounded by $\sum_c |v_c|\,|p_c-\hat p_c|$. These bounds concern the probabilities actually consumed by the readout; separately rounded API fields require direct checks. Agreement of the winning label alone is thus insufficient for probability-sensitive applications.

\section{Implementation}
\subsection{Adapters and selective graph replay}
The runtime loads an immutable checkpoint revision and uses an adapter to invoke the released inference engine. DFIP wraps a compatible forward boundary with static input buffers and a shape cache. A key records tensor dimensions, strides, dtype, device, and supported scalar metadata. Replays copy current inputs into the captured buffers; the cache stores computation, never a previous prediction. Calls sharing mutable buffers are serialized in the serving engine.

The v1 tested policy admits a shape after three encounters and bounds the graph cache to four entries. Liquid, Clef, and PPLX-Decider use a 512-token capture limit. Clef and PPLX-Decider limit capture to a single forward row. Unsupported paths use the released native implementation. PPLX-Decider's hybrid recurrence path additionally keys valid lengths, since shape equality alone cannot prove control-flow equivalence. For Julia, an equivalent local attention mask is constructed on the GPU to make capture possible. These adaptations are implementation choices rather than claims of novel graph scheduling.

Captured allocation lifetime is another constraint. The first expanded protocol encountered illegal GPU memory access in three checkpoint applications. The error was observed during benchmark execution, sometimes after a mode transition; asynchronous reporting does not identify the responsible kernel. Failure excerpts are retained. A follow-up implementation synchronizes before clearing or evicting a graph. A 60-call synthetic-kernel test covering shape eviction and cache clearing passes, but Julia still fails during the new-workload fidelity run after this change. This does not resolve the model-level failure, and we do not pool the follow-up with the original protocol. After the strengthened serving study also exposes Decider replay errors and recapture overhead, the review branch defaults all five checkpoints to native inference. Experimental replay and head paths remain available through research entry points and a separate opt-in adaptive app; Security-One retains its native SGLang substrate, with concurrent native dispatch in the review source. Existing deployed applications were not changed.

\subsection{Post hoc bounded admission prototype}
After observing v3 recapture losses, we add an exploratory policy that tracks the last 128 eligible calls. Admission waits for at least 32 eligible calls in the window; a shape then needs eight matching hits and frequency at least 12.5\%. A configuration permits at most four capture attempts, including failed attempts, and pins admitted graphs without eviction. Other shapes execute natively. This bounds capture attempts rather than guaranteeing latency or automatically adapting the resident set to future popularity shifts. Reconfiguration or a new worker resets the budget. Native fallback does not recover a CUDA context damaged by an illegal-memory-access fault.

The separate opt-in API limits replay to one categorical question on one record, retaining the inherited 512-token, single-row capture limits. Other request schemas use native inference. GPU access remains serialized. The native application remains the default. These source changes were prepared for review; existing deployments were not reconfigured.

\subsection{Candidate heads and rejected kernels}
For d1-3B, the adapter derives answer-token groups using the released tokenizer and readout code. A head projects the verified union with either a Triton reduction kernel or PyTorch's linear operation. New groups extend that union and invalidate existing captures. To preserve the released engine's tensor interface, the current prototype reconstructs a vocabulary-shaped tensor with uncomputed positions set to negative infinity. It therefore removes much projection arithmetic but retains output allocation, scatter, and readout overhead. This is an explicit limitation rather than a minimal-width output implementation.

Security-One's experimental SGLang patch projects its verified answer-code rows at the native output boundary. It is isolated from the selected deployment policy, which remains native SGLang. The comparison uses both Triton and cuBLAS-backed projection. Experimental RMSNorm replacements and released compiler options from the earlier development study are retained as supplementary evidence. They are not enabled merely because a local kernel test passes: full-model probability and decision checks determine whether a path is admissible.

\subsection{Modal execution and packaging}
GPU workers use pinned model revisions and persistent remote volumes. The local package depends on the Modal client, not PyTorch or checkpoint weights. It exposes preparation, deployment, inference, and validation commands, while accelerator dependencies live in remote images. Deployment can scale to zero. The study initially ran model applications concurrently and reached the workspace's GPU concurrency limit; subsequent workers are capped at one container, and follow-up experiments are serialized. Concurrency changes how quickly experiments finish and is not a source of model acceleration.

\section{Experimental Method}
\subsection{Hardware, software, and baselines}
Julia, d1-3B, and Clef run on one NVIDIA L40S each; PPLX-Decider and Security-One run on one NVIDIA B200 each. Worker requests use four CPU cores and 32~GiB of host memory for the smaller models, and eight cores and 96~GiB for the larger models. Per-round GPU identity, driver, CUDA version, core package versions, and container identity accompany the raw samples. Separate CPU-only inventories list all installed packages in the v3 image definitions; they are supplementary environment evidence rather than additional GPU rounds. The Transformers reference images use PyTorch 2.14.0, CUDA 13.0, Triton 3.8.0, and Transformers 5.17.0; Julia uses Transformers 5.0.0. Security-One uses the SGLang 0.5.19 CUDA 13 image.

The primary baseline is the released eager/native adapter in the same environment. This is not a comparison against every optimized serving engine. In particular, the initial Qwen reference environment lacks the optional \texttt{causal-conv1d} extension and uses a PyTorch fallback. An optional extension build is recorded separately; results from such a build must not be mixed with the fallback baseline. Consequently, gains for Clef and PPLX-Decider cannot be interpreted as improvements over an optimized-kernel ceiling. SGLang already supplies an optimized serving substrate for Security-One.

\subsection{Workloads and fidelity sets}
Nine timing workloads cover a short Boolean decision, a short categorical decision, three questions on one state, medium and long repeated-log contexts, candidate widths 2, 8, and 16, and eight requests in one batch. The exact states and schemas are defined in the artifact. Contexts are synthetic; token counts differ across released prompt encodings. A 120-call trace changes state content and lengths across 40 context sizes to test admission and replay without prediction caching.

The first fidelity set contains 400 typed-decision cases with 2,000 questions from the pinned \texttt{LocalLLaMA/typed-decisions} test split. This set was used during earlier DFIP development and is not a pristine holdout. A second workload samples 256 test utterances from BANKING77~\citep{banking}. For each utterance, we construct one single-choice record and one record containing choice, Boolean, and ordinal questions: 512 records and 1,024 decisions in total. Choice candidate widths cycle through 2, 4, 8, and 16 and include the gold intent. Boolean targets alternate between matching and nonmatching intents. Derived ordinal questions are diagnostic and have no validated annotation. Dataset revision hashes, content checksums, seeds, and generated-record hashes are included. Checkpoint training overlap with either corpus is unknown.

We compare complete returned probability distributions, their argmax labels, probability-derived expected ordinal scores, and probability-slot threshold crossings at 0.1, 0.25, 0.5, 0.75, and 0.9. Clef rounds probability slots after selecting a categorical answer and computes its returned score from unrounded probabilities. The original v1/v3 distribution reports therefore do not independently establish literal answer-field equality at rounded ties. Separate instrumented v3 audits compare returned choice, score, and confidence fields directly on all 3,024 decisions; later serving records also retain these fields. Measured probability drift concerns the released interface rather than unrounded internal logits. Diagnostic accuracy, Brier score, and equal-width expected calibration error are available for the derived choice/Boolean labels, but repeated single-choice and multi-question views of one utterance are correlated. They are not independent quality examples.

\subsection{Timing and statistical unit}
The protocol plans five independent single-use container rounds per checkpoint, with 50 timed calls per workload and mode after four admission/warmup calls. Mode and workload orders are randomized by round. GPU synchronization brackets the resident Transformers API timing, which includes encoding, forward computation, and native readout. Security-One timing includes the in-container HTTP client and SGLang scheduler. It excludes external client networking and server startup. Its native runs bracket the randomized head experiments to expose drift across server restarts.

The statistical unit is a container round. We compute each workload's median within each round, pair native and tested-policy medians, and report their geometric-mean ratio. Intervals are 95\% percentile bootstrap intervals over paired log ratios with 10,000 resamples; the 50 calls are not treated as 50 independent deployment replications. Small samples and cloud variability remain limitations. For Security-One, the within-round reference is the geometric mean of the two native medians.

Julia's initial application returned no complete expanded-protocol round. Liquid and Clef each returned three rounds before an application-level GPU error aborted the remaining work. PPLX-Decider and Security-One completed five rounds each. Security-One's last container also emitted driver graphics-exception warnings before the first measured mode; the function continued and returned a complete round. We retain these warnings without assigning a kernel root cause. Tables are generated from complete retained JSON records and report actual counts. Attrition can be nonrandom, so intervals based on retained runs are conditional and may be optimistic. We do not impute failed rounds or substitute old one-container samples as independent repetitions.

\subsection{Strengthened native and serving protocol}
We freeze a separate v3 protocol rather than pool new measurements with v1. For Clef and PPLX-Decider, five single-use container rounds are planned with the same nine workloads, randomized native/DFIP order, and 50 warm samples. The image adds \texttt{causal-conv1d} 1.7.0 to \texttt{fla-core} 0.5.2 for the released Qwen linear-attention path~\citep{qwenkernels}. SDPA and PPLX-Decider's noncausal attention semantics remain intact. This is a stronger same-image native comparison, not a claim to equal every specialized backend; differences between the old and new images cannot isolate the causal effect of extension installation. A separate three-round Liquid experiment compares native eager, the released runner's \texttt{torch.compile(mode="reduce-overhead")} setting~\citep{torchcompile}, and DFIP on three short workloads. It checks 128 single categorical requests with changing content, length, and candidate width; this compiler fidelity check does not cover every Boolean or ordinal timing schema. Compiler admission and failed modes are retained.

The serving study plans three independent application/container rounds for Clef, PPLX-Decider, and selected native Security-One. The first two compare native with experimental graph replay in randomized mode order within one worker. An external author workstation with Swedish network egress sends authenticated Modal RPC requests at fixed open-loop rates of 5, 15, and 30 requests/s for 60 seconds each. Contents, twelve recurring state-repetition counts, and candidate widths 2/8/16 change deterministically. This diversity stress case can exceed the four-entry graph cache; it does not estimate steady-state serving for a single captured shape. The payloads also differ from the resident short Boolean workload, so serving throughput is not divided by its latency to infer a workload-independent gain. Latency starts at scheduled arrival, includes client dispatch delay, transport, and queueing, and ends when the result returns. Each phase drains fully before the next. Worker initialization and 48 admission calls are recorded separately. Checkpoint and compiler artifacts persist in the remote volume; initialization is not an empty-cache download or compilation benchmark.

The worker accepts up to 64 concurrent RPC inputs. A lock serializes Transformer GPU computation to protect mutable capture buffers. Security-One separately compares this serialized client dispatch with concurrent requests to the native SGLang scheduler, which owns its GPU state and can batch requests. Existing engine settings remain fixed, including 32 maximum running requests, disabled radix caching, and SGLang's own CUDA graph execution. Native SGLang therefore already includes backend optimizations; the comparison changes wrapper dispatch rather than tuning the entire backend. In that mode the reported wrapper queue is zero by construction; service time includes the internal HTTP request and scheduler queue, which are not separated by this instrumentation. The client permits 128 requests in flight; excess arrivals are counted as dropped. Errors and drops stay in the offered-load denominator. Tail latency is conditional on successful requests and is reported alongside loss and within-window completion throughput. We aggregate per-container quantiles, not thousands of calls as independent hardware replications. Before/after checks use 128 matched requests; returned stream distributions enable additional ID-matched comparisons across modes, with unmatched requests counted separately. These are minute-scale tests of these wrappers, not a tuned dynamic-batching throughput ceiling or hours-long production reliability certification.

\subsection{Separate adaptive pilot}
The post hoc v4 protocol plans one new container each for Decider and Clef, comparing native and bounded admission in randomized order with the v3 optimized-native image. Each mode first receives the original diverse trace, then a synthetic mixture of 60\% recurring short request family with changing ticket content and 40\% original diversity. The short family fixes the state-repetition count and two-candidate schema, but ticket tokenization can still change exact sequence length. Each profile uses the same three rates and 60-second phase duration, with native setup and fidelity checks before enabling admission. Cache state persists across rates and profiles within a mode; mixed-profile results therefore include diverse-profile history. Final checks freeze admission but can replay captured entries. This is a diagnostic popularity mix, not measured production traffic. Results are separate from v3 and have no confidence interval or independent reliability replication.

Clef's first attempt returns client status \texttt{complete} but changes worker identity during adaptive traffic; the replacement finishes in native mode with no admitted graphs. We retain and exclude the whole comparative trial. A recorded amendment adds actual worker identity/mode checks to every response and final audit, and increases the idle window from 10 to 300 seconds before a separate corrected trial. The cause of replacement is unknown, so this precaution does not establish an idle-scaling root cause.

\subsection{RQ3: Decision agreement is weaker than fidelity}
Appendix Table~\ref{tab:fidelity} combines the two fidelity sets for complete v1 round-zero results. No tested policy in the table changes an argmax reconstructed from returned probabilities or crosses the five sampled probability thresholds. Nevertheless, d1-3B and Clef exhibit measurable drift on the new workload. The absence of crossings at these five thresholds does not establish safety for arbitrary thresholds close to a model confidence, and exact real-arithmetic projection does not imply bitwise equality.



The Security-One cuBLAS-backed candidate head provides a clear counterexample to using label agreement as the only gate: it preserves all 2,000 returned-distribution argmax labels in the typed set but reaches a maximum probability difference of approximately 0.0393. The Triton variant is much closer to the native probabilities, with a maximum difference below $2\times10^{-7}$ on that set. Neither result proves that candidate projection yields a worthwhile full-request speedup on the SGLang substrate. The selected deployment therefore retains native SGLang. A separate single-container Clef follow-up with the optional native convolution extension also preserves returned-distribution argmax labels, but produces two sampled threshold crossings and a maximum new-workload probability difference of 0.0129 (Appendix~\ref{app:followup}). This is a concrete probability-sensitive failure even when argmax agreement is complete.

Table~\ref{tab:literal-audits} reports the separate literal-readout audits, each evaluating 3,024 decisions. PPLX-Decider has zero probability drift, zero changes in 1,112 returned choice fields, and zero drift in 1,056 score and 2,168 confidence fields on this sample. Clef also preserves all 1,112 returned choices, but has maximum returned score drift 0.0188 and confidence drift 0.0129. Its probability-slot crossings at 0.1 and 0.25 reproduce the earlier negative result. These are single-container audits with fixed native-then-DFIP order, not additional independent timing rounds. In particular, the observed Clef probability crossings are not demonstrated Boolean accept/deny flips.

\subsection{RQ4: External arrivals and serving limits}

Figure~\ref{fig:serving} summarizes serving behavior; Table~\ref{tab:serving} in the appendix reports observed phases, including completed phases from containers that later fail. Counts differ when a failure prevents later rates or modes; omitted phases are not successful zero-loss measurements. Tail quantiles concern successful requests, while the loss denominator contains all offered arrivals. Container-level tail ranges are retained in the artifact because cloud variability is large.

All three PPLX-Decider attempts are retained: two complete and one fails with CUDA illegal-memory-access errors during its first graph traffic phase, after completing all native phases. At 5 offered requests/s, native has zero loss with a geometric-mean p95 of 0.81\,s. The graph path yields only 2.04 within-window completions/s, 23.0\% loss, and a successful-request p95 of 49.41\,s (container range 21.79--76.55\,s). At 30 offered requests/s, the two observed graph phases have 83.1\% loss. The two complete graph rounds preserve returned choices and probabilities on matched traffic; all three together provide only 1,761 matched successful request pairs across rounds, with repeated trace inputs. This selected subset cannot certify omitted or failed requests.

The diagnostics expose frequent recapture: the second Decider attempt, which completes, records 820 captures and 915 replays, including admission and fidelity checks, with most replays therefore occurring in the same call as capture. At 30 offered requests/s its graph service median is 524\,ms versus 129\,ms for native. This supports recapture overhead as an explanation for the performance reversal on this diversity stress case, but does not localize the asynchronous CUDA fault or establish performance for a single recurring shape. It rules out extrapolating the resident 2.47$\times$ gain into a general serving claim. The review package consequently defaults Decider to native, with replay available through experimental entry points; existing deployments are unchanged.

All three Clef serving rounds complete without request errors. At 5 offered requests/s, native has zero loss and p95 0.34\,s; replay has 4.9\% loss, 2.68 within-window completions/s, and p95 39.44\,s. At 30 offered requests/s, replay loses 83.1\% of arrivals versus 54.3\% for the serialized native wrapper. No returned choices change among 2,473 matched successful request pairs across rounds, but maximum probability and returned-confidence drift is 0.0056. Twenty-one of these pairs cross the literal returned-confidence threshold 0.9, with repeated trace inputs across rounds. This differs from the earlier ordinal probability-slot crossings: it directly changes a hypothetical confidence-threshold routing policy, without demonstrating worse task accuracy or a Boolean answer flip. The native-preflight failure in the separate optimized resident experiment remains a distinct reliability outcome.

All three Security-One rounds complete. Concurrent dispatch to the same native SGLang engine sustains 29.76 within-window completions/s at 30 offered requests/s, with no drops or request errors and geometric-mean p95 0.65\,s (range 0.55--0.71\,s). Serialized dispatch gives 18.33 completions/s, 31.8\% drops, and p95 6.95\,s. The benefit is workload dependent: at 15 requests/s, concurrent p95 ranges from 0.43 to 3.56\,s and its geometric mean is slightly higher than serialized dispatch. All 7,283 matched successful request pairs across rounds preserve literal choices; maximum probability drift is $1.56\times10^{-15}$, with no sampled crossings. This is a wrapper-dispatch result using an already optimized native engine, not evidence for a custom output-head kernel or a uniform latency improvement. Its minute-scale scope and selected matched subset remain limitations.

\subsection{Post hoc bounded-admission results}\label{sec:adaptive-results}
The separate v4 pilots bound capture work to four successful captures and four resident entries per validated worker, with no recorded request errors. Decider records 474 replays and corrected Clef records 400, including final fidelity checks and the immediate replay after each capture. Most calls still execute natively. These observations verify the budget on these runs, not general CUDA reliability or superiority to the v3 LRU policy on the same worker.

Decider completes both modes in one container with native first. At 5 requests/s, both profiles have zero loss, but adaptive p95 is higher on the diverse trace (0.48 versus 0.32\,s) and lower on the mixed trace (0.35 versus 0.48\,s). At 30 requests/s, diverse adaptive/native within-window completions are 9.62/7.53 per second, with 60.8/67.8\% loss; mixed completions are 8.22/7.65, with 65.5/67.4\% loss. Improvement is modest and uneven, while overload remains substantial. All 2,057 matched successful categorical pairs preserve literal choices, probabilities, and returned confidence on this sample. Omitted requests and untested ordinal/Boolean schemas remain outside this fidelity result.

Corrected Clef runs adaptive first in one worker and completes both modes without request errors. At 5 requests/s, adaptive p95 is slightly higher than native on both traces (0.42/0.36\,s diverse; 0.35/0.34\,s mixed). Both modes sustain 14.93 within-window completions/s at 15 offered requests/s without loss. At 30 requests/s, adaptive/native completions are 15.88/15.95 per second on the diverse trace and 16.55/16.25 on the mixed trace, with roughly 38--40\% drops. There is no consistent latency or capacity advantage. All 3,844 matched successful categorical pairs preserve returned choices, but maximum probability and returned-confidence drift reaches 0.0065; fourteen mixed-trace pairs cross the returned-confidence threshold 0.9. Bounded admission therefore does not establish confidence equivalence. These one-container findings support an opt-in policy experiment, while leaving batching, numerical tolerance, popularity shifts, and long-duration reliability unresolved.

\section{Cost Interpretation and Deployment Limits}
At Modal's listed rates on October 12, 2026, an L40S costs \$0.000542 per GPU-second and a B200 costs \$0.001736~\citep{modalpricing}. A narrow compute estimate for $D$ decisions per call is
\begin{equation}
 C_{1000}^{\mathrm{GPU}}=1000\,r_{\mathrm{GPU}}\,T_{\mathrm{call}}/D,
\end{equation}
where $T_{\mathrm{call}}$ is in seconds. The artifact computes this quantity from the retained medians. It is not a measured invoice or a cost-per-request claim for a network service. CPU, memory, model loading, graph admission, idle container lifetime, storage, networking, and plan fees are excluded.

For $N$ calls within one billed container lifetime, a more useful approximation is
\begin{equation}
 C\approx r_{\mathrm{resources}}
 (T_{\mathrm{load}}+T_{\mathrm{admit}}+NT_{\mathrm{serve}}+T_{\mathrm{idle}}).
\end{equation}
Modal bills load and processing time and the configured idle window~\citep{modalpricing}. For sparse traffic these terms can dominate a small kernel reduction. Capping benchmark concurrency avoids a plan upgrade but does not make a fixed amount of GPU work free. The v3 serving protocol adds external transport, fixed arrivals, queueing, and tail-latency measurements to the resident study. It still does not establish production traffic representativeness, measured billing savings, or invoice reconciliation. A resource-rate estimate must not be presented as an observed bill reduction.

\section{Related Work}
SGLang~\citep{sglang} combines structured language-model programs with a runtime that reuses execution structure. DFIP uses a narrower native decision contract and does not claim structured selection as a new primitive. PagedAttention and vLLM~\citep{vllm} address KV-cache memory management and serving throughput for generation; those mechanisms and their arrival-rate evaluation are distinct from this serial decision-path study.

PyGraph~\citep{pygraph} develops compiler support for robust CUDA graph use and evaluates component contributions across workloads. Its broader treatment makes clear that a small shape cache is not a novel graph compiler. PyTorch's CUDA graph documentation~\citep{cudagraphs} also specifies static-address and control-flow constraints. Triton~\citep{triton} provides a tiled programming model for custom GPU computation; DFIP applies it to a small candidate projection rather than proposing a new language or tensor primitive.

MLPerf Inference~\citep{mlperf} emphasizes workload scenarios, quality constraints, and latency/throughput measurement. This informs our separation of fidelity from timing, but the present study is not MLPerf-compliant and does not measure all of its serving scenarios. BANKING77~\citep{banking} supplies an independently sourced intent workload; deriving a finite candidate set from its labels is our diagnostic construction, not the original benchmark task or a new validated scoring dataset.

\section{Threats to Validity and Open Work}
\textbf{Baseline strength.} Optional native convolution kernels are absent in the initial Transformers environment. The separate v3 comparisons add native CUDA kernels and a released compiler setting, but do not exhaust tuned serving backends. \textbf{Selection and attrition.} Five checkpoints are chosen for interface diversity. Failed rounds are not missing at random, and three-round conditional intervals provide weak evidence of population stability. Julia lacks a complete initial expanded-protocol result.

\textbf{Workload validity.} The post hoc adaptive policy has one validated container per model, fixed diverse-before-mixed history, and no direct same-worker LRU-versus-pinned comparison. Its small pilot cannot establish that prior CUDA failures are resolved. Timing states are synthetic; the serving study uses one external client geography and three fixed arrival rates over minute-scale windows. It cannot establish hours-long reliability, burst resilience, autoscaling behavior, or a Transformer dynamic-batching ceiling. BANKING77 schemas are derived, and duplicated utterance views are correlated. The typed set was used during development, and checkpoint training overlap is unknown. Image paths, adversarial states, maximum supported contexts, and multi-GPU configurations are untested here.

\textbf{Numerical validity.} Returned probabilities may be rounded, calibration magnifies some logit differences, and five threshold values cannot cover all application policies. No observed label flip is a finite sample statement. Observed drift is not localized to one kernel; capture compatibility and arithmetic differences may both matter. Dynamic candidate coverage and graph admission interact with workload order. The initial failure's asynchronous traceback cannot establish a kernel-level root cause, and a conservative synchronization change requires independent validation.

\textbf{Reproducibility.} Model and dataset revisions and package versions are recorded, but cloud scheduling, server placement, hardware contention, driver updates, transitive dependencies, and graph-library behavior are not fully controlled. Fresh containers do not guarantee independent physical hosts. The artifact preserves source versions and failed runs. Before an arXiv submission, the authors should review the failures and numerical differences, freeze a publicly accessible artifact, and check every generated table against the archived results. Cloud experiments and a manuscript draft do not replace author review.

\section{Conclusion}
DFIP shows how a lightweight, model-aware decision inference implementation can combine native semantics with established replay and candidate-readout techniques. The retained results favor selective graph replay for repeated short workloads and provide weaker evidence for custom output projection as a full-request optimization. Probability drift, GPU failures, and recapture overhead under diverse arrivals define meaningful boundaries of the current prototype. A warm isolated-call gain does not by itself justify enabling replay for changing serving traffic. Concurrent native SGLang dispatch improves the tested Security-One service, while post hoc bounded admission limits capture work without establishing uniform gains or confidence equivalence. The contribution is the characterization and reproducible evidence, including rejected paths.
