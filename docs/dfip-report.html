Decision-focused inference, measured

DFIP is built and runs on Modal. Five open-weight decision checkpoints were tested with their native prompt formats, scoring rules and calibration. The chosen runtime improves short-request latency primarily through CUDA graphs; Liquid adds a small Triton candidate-projection gain. Security-One retains its optimized native SGLang path.

What is enabled

  • Julia: equivalent attention masks built on the GPU, plus CUDA graphs; the marker-only head change is excluded because it shifts probabilities.
  • Liquid: a verified, dynamically expanding answer-token union, a Triton projection kernel, and CUDA graphs for short single-question calls. Native packed-tree inference handles multiple questions and batches.
  • Clef: CUDA graphs for short single-record backbones. Larger inputs and batches use the native path.
  • Perplexity: native noncausal attention, mean pooling and calibration are preserved. Graph capture keys include valid lengths. Graphs are limited to single-decision forwards; batches and multiple questions use the native path after a padded hybrid graph stress-test failure.
  • Security-One: native SGLang 0.5.19 with BF16 weights, TensorRT-LLM attention and float32 recurrence state. The candidate-only heads remain benchmark experiments.

Fidelity and dataset quality

The deployed text paths were checked against native inference on all 400 cases (2,000 typed questions) in the pinned LocalLLaMA/typed-decisions test set. All four in-process models also ran 128 varied single-question stress cases. Clef preserved every decision with at most 0.001 probability drift in those extra calls, within a 0.1 percentage-point allowance; the other chosen paths were unchanged at the measured precision. Liquid’s public dataset cases use its native packed-tree path; changed-input graph tests and a 64-option schema test cover the single-question graph and dynamic token coverage. Probabilities are compared at the published API precision; Clef rounds to four decimals.

Security-One head ablation

The full vocabulary head was compared with 255 verified answer-token rows using cuBLAS and Triton. The unused generated token is discarded; conditional candidate probabilities cancel the vocabulary normalizer. The native engine was repeated at the end to expose run variation. Its short-request latency shifted substantially between native runs, so a head-only speedup is not established. cuBLAS also shifted some probabilities despite preserving argmax; the Triton drift was much smaller. The small head savings do not justify enabling a new runtime path for this model.

Deployment and reproduction

The authenticated Modal app is dfip-inference, with classes Julia, Small, Decider and Security. It scales to zero after the warm idle window and exposes no public HTTP endpoint. The volume dfip-research-v1 contains pinned checkpoints, datasets, caches and complete results. The existing production app was left untouched.

The source archive includes deployment, benchmarking, kernels, adapters and validation. Model weights are not included. This release covers text-only decisions and bounded contexts; it does not benchmark image/video inference, internet round trips, concurrent serving load, or arbitrary untested model families.

Clef and Perplexity’s Transformers baseline uses fla-core 0.5.2 but lacks the optional causal-conv1d extension; its convolution uses the reference implementation. Their absolute latency is therefore not a fully optimized serving ceiling. Security-One uses the independent optimized SGLang baseline.
